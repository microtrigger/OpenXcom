# Supervised stance: finite native evidence

Recorded 2026-10-11. See the [machine-readable evidence](supervised-stance-evidence.json)
for exact source and binary SHA-256 identities, retained initial results,
per-master outcomes and intended sensitivity assertions.

## Corrected results

Both UFO (`xcom1`) and TFTD (`xcom2`) passed the real native gate. Each completed
12 manual-versus-controlled pairs, 19 adversarial worlds and two fresh
post-action panel checks. Ordinary SDL control, the real confirmation modal,
normal kneel handler, actual reaction queue and final physical display were
exercised. The feature and the fixture are separate default-OFF build options.

Five real-source controls were rebuilt against the unchanged frozen fixtures.
All ten runs, one per control per game, failed on their first attempt at the
intended native assertion:

- Wrong actor and wrong TU: expected original actor/stance/4-or-8-TU outcome
- Duplicate dispatch: second normal UI callback
- Reaction bypass: missing actual queued reaction
- Unseen modal: a callback caused by Y before the first modal presentation

These were real native-path mutations, not mocked or fabricated output failures.

## Initial failure is retained

The initial UFO run passed; the initial TFTD run failed at the old field-shape
assertion 182. TFTD resizes its buttons, which leaves the unused base surface
marked for redraw while a selected button displays a separate ready alternate.
The original base-only visibility guard wrongly rejected that actual display.

The correction checks the displayed alternate through a control-only virtual
visibility method. Parent visibility/cropping and exact geometry remain checked;
ordinary rendering/cache behavior is unchanged. A native regression now blits
actual temporary button surfaces and exercises the precise distinction. Both
games were rerun successfully after this correction; the initial failure was
not replaced or counted as a pass.

## Actual MCP/native demonstrations

UFO and TFTD each passed a separate real official-MCP-SDK/adapter/native-game
demonstration. Each used seven public calls, returned three public panel images
and obtained two dispatched receipts after local operator confirmation. Fresh
panels were visually checked: standing at 40 TU, kneeling at 36 TU, then standing
at 28 TU. These observations, rather than the receipts alone, establish the
nominal visible outcome.

Both used the same unchanged native controller binary. A separate test setup
created the initial ordinary battle fixture; no private state oracle or
client self-approval was used afterward. Driver logging changed between runs.
The TFTD driver hash was verified before launch; the UFO launch-time driver hash
was not recorded. No identical-driver-hash claim is made.

Seven earlier unsuccessful UFO attempts are retained: one interpreter setup
failure before the game started; three unchanged-controller context refusals
with zero established dispatches; two isolated diagnostic-only runs excluded
from acceptance; and one local-confirmation/status stop with no established
dispatched receipt. The context refusals came from a cursor still covering the
actually rendered HUD. Fresh ordinary movement after display restored the
supported profile without relaxing controller validation. No uncertain command
was automatically reissued; successful demonstrations were explicit new runs.

## What this establishes

The finite gate checks 4/8 TU costs and exact/insufficient boundaries,
reservations, same-looking actor races, manual/overlay/focus/save replacement,
context changes, local cancellation, replay/conflict/disconnect handling and
premature or held-input approval rejection. Two nominal cases obtain fresh
post-dispatch context and match the independently sampled manual final panel.

Reaction cases establish immediate real-queue parity before normal simulation
consumes it. They do not verify a finished post-reaction visible outcome.
Focus tests use SDL notifications; load tests replace actual save/state objects.
They are not window-manager or disk load-dialog tests.

The final default-OFF
rebuild passed and contains no stance/controller/gate symbols or activation
strings; it is bit-identical to the initial default-OFF binary. There is no full
Stage 5 closure, timing-equality guarantee or token-savings measurement here.
No assets, executables, saves, raw states, captures or capability tokens are
published with this evidence.
